# Core Query Loop column parity

The Portfolio pattern is a native WordPress Query Loop. Its Query block contains only Core-supported query attributes; the legacy `displayLayout` key is intentionally absent because current Core registers layout on the Post Template block rather than on Query. Slateframe's opt-in legacy-flex presentation still supplies the initial three-column grid, and an author may choose a native Core Grid in Gutenberg without Slateframe overriding that grid. A real WordPress browser assertion checks the registered pattern for stale Query metadata.

Slateframe must respect the author's Core `columns-1` through `columns-6` choice instead of forcing three desktop columns. On tablet widths (641–900px) the layout caps at two columns without turning a deliberate single-column layout into two. At 640px and below it uses one column.

When Core chooses `is-layout-grid`, the Core grid layout remains authoritative; Slateframe only overrides the legacy flex template. The footer retains its own single-column rule. All controls, typography, links, dates and featured-image behavior remain unchanged.

Validation: `python3 -m unittest tests/test_portfolio_columns_contract.py`; `tests/browser/portfolio-core-columns.spec.js` runs against the real WordPress Portfolio fixture in Theme quality. Inspect exact-SHA 390/1440px screenshots and Core editor parity before merge. Earlier isolated Chromium verification exercised 360 combinations of 320–1920px, 1–6 columns, RTL/LTR, editor/front-end and Core Grid, but it does not replace WordPress Actions.

## Readable 200% and 400% text enlargement

A six-column Query Loop can avoid document overflow yet leave only a few characters per line at 400% text size. Slateframe uses a **named inline-size container** on the opt-in `slateframe-project-grid` pattern and a `35rem` container threshold. Since `rem` follows the root text size, native legacy-flex Post Templates collapse to one readable column at 400% for all seven supported widths, and at 200% where the container is narrower than 1120px. This is not a global viewport breakpoint or hidden overflow workaround. At normal text size, authored 1–6 columns and existing 640/900px caps remain unchanged. Authored Core `is-layout-grid` stays authoritative.

The tiny `portfolio-reflow.css` is loaded after `query-loop.css` only with a Query Loop and is shared with Gutenberg. Browsers without container queries retain the existing mobile/tablet fallback. A review caught a 641–680px regression with the former 40rem threshold: normal-size gutters could shrink the container below 640px even though the viewport was still in the two-column tablet band. The 35rem threshold retains authored 1–6 columns at 641, 650, 680, 720, 768 and 900px in LTR/RTL; two 680px baseline screenshots are mandatory. Browser acceptance exercises six authored choices, seven widths, LTR/RTL, CJK/Arabic long titles, keyboard target geometry, and Core Grid at 400%; Theme quality requires fourteen 400% LTR/RTL screenshots at all seven supported widths, two 680px tablet baseline screenshots, and a 390px RTL/400% forced-colors focus screenshot. The real WordPress browser test also runs axe WCAG 2.1 AA checks on the Portfolio region at 400%; screenshots and static contracts do not replace actual runtime verification. Manual Firefox/Safari and Gutenberg visual review remain necessary.

## Keyboard focus and sticky-header clearance

Real Portfolio element crops exposed the sticky site header overlapping the top of the first card at desktop widths. The theme now gives **native Portfolio links** a logical block-start scroll margin equal to the responsive header minimum plus one stack gap, **only above 480px**, where the header is sticky. The rule lives in the existing **conditionally loaded Core Post Title stylesheet** (`core-post-title.css`), not the universal CSS or a new asset. It applies to native Core Post Title blocks in Portfolio Query Loops on singular pages and archives, and Gutenberg shares the stylesheet. The offset uses the header-height token plus a half-rem focus buffer. Core title's redundant box-sizing (already universal) and inherited child overflow-wrap were removed without changing their computed presentation to keep the original 400-byte asset budget. Plugin-generated markup without a rendered Core Post Title block does not automatically load this conditional asset. Mobile widths keep the existing non-sticky header and receive no unnecessary scroll offset. The rule changes anchor/focus scroll positioning only; it does not hide cards, alter Query Loop column choices, or relax the 44px control target.

The real WordPress browser regression scrolls a native Core Post Template title link into view, checks its actual top edge against the sticky header bottom, checks the computed scroll margin against header height, verifies focus outline and minimum link height, and rejects document overflow. It covers 768/1440px at 100%, 200% and 400% root text size in LTR/RTL, plus 320/375/390/412px mobile at 400%, with a 768px RTL forced-colors/reduced-motion pass. Three screenshots are required by Theme quality: `portfolio-focus-scroll-390-rtl-400.png`, `portfolio-focus-scroll-768-rtl-200-forced-colors.png` and `portfolio-focus-scroll-1440-ltr-400.png`. These are **new exact-SHA acceptance gates**, not proof of success until the corresponding WordPress/Chromium Actions and actual images are inspected. If a long translated header grows taller than the token allowance, fix the actual clearance rather than weakening the geometry assertion.
