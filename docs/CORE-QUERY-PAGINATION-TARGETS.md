# Native Core Query Pagination targets

Slateframe keeps **Core Query Pagination** as native WordPress markup. It does not intercept navigation, replace the Query Loop, own post types, or add JavaScript. The generic Core selector is registered for `core/query-pagination` via `wp_enqueue_block_style()`. WordPress may inline that asset rather than emit a separate stylesheet URL; runtime tests assert computed behavior. Gutenberg also receives the same small block stylesheet through `add_editor_style()`. The existing 44px base geometry stays in `style.css`.

## Interaction and visual contract

- Numeric page links, the active page number, Previous, and Next already use the bounded `--slateframe-control` target (44px minimum; 44–56px via Appearance). Even a single digit remains a usable target.
- The current page remains a non-link, retaining Core's semantics. It now has the same emphasized ink/paper appearance in ordinary Core Query Loops as in Portfolio. Under forced colors its visible `Highlight` outline with zero offset matches the existing article pagination contract without relying on background color.
- Localized labels can wrap without pushing controls outside the viewport; existing logical padding and grid centering are preserved while explicit overflow wrapping and tabular numerals stabilize mixed-script navigation in LTR and RTL.
- Theme-wide focus-visible styling continues to provide a keyboard outline. No navigation interception or synthetic click behavior is introduced.
- The native Portfolio Query Loop fixture also removes its Portfolio presentation wrapper in a separate runtime case, proving the block styling works in a generic Core context. The main test verifies real Core markup, a deliberately long translated Next label, both pages and back-navigation, 320/375/390/412/768/1440/1920 widths, LTR/RTL, 100%/200% and representative 400% root text sizing, keyboard focus, forced colors and Axe. Screenshots are generated by WordPress+Chromium on the exact CI checkout SHA.

## Printed reading

Core Query Pagination is interactive navigation, not article content. Its conditional block stylesheet hides only the native pagination wrapper under print media; the Query Loop posts, their authored content and surrounding editorial context remain printable. This does not change screen navigation, page-number semantics, or WordPress query behavior. The real WordPress browser test checks Portfolio and generic Core contexts, restores screen media, and requires a 390×900 RTL print-mode viewport screenshot in CI.
