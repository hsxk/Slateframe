# Native Core Query Pagination targets

Slateframe keeps **Core Query Pagination** as native WordPress markup. It does not intercept navigation, replace the Query Loop, own post types, or add JavaScript. The generic Core selector applies in the frontend and Gutenberg editor because `style.css` is registered as an editor stylesheet.

## Interaction and visual contract

- Numeric page links, the active page number, Previous, and Next use the bounded `--slateframe-control` target (44px minimum; 44–56px via Appearance). Even a single digit remains a usable target.
- The current page remains a non-link, retaining Core's semantics. Under forced colors its visible CanvasText outline distinguishes it without relying on background color.
- Localized labels wrap instead of pushing controls outside the viewport; logical inline padding, tabular numeric widths, and centered labels work in LTR and RTL.
- Theme-wide focus-visible styling continues to provide a keyboard outline. No navigation interception or synthetic click behavior is introduced.
- The native Portfolio Query Loop fixture verifies both pages and back-navigation, 320/375/390/412/768/1440/1920 widths, LTR/RTL, 100%/200% and representative 400% root text sizing, keyboard focus, forced colors and Axe. Screenshots are generated by WordPress+Chromium on the exact CI checkout SHA.
