# Core Button palette and outline parity

Slateframe presents **native WordPress Core Buttons** without replacing Gutenberg's authored colors, changing saved markup, or adding JavaScript. The base button rule owns only bounded control geometry, spacing, wrapping, border and focus affordances. The theme's ink/paper default is applied **only when the corresponding Core `has-background` or `has-text-color` marker is absent**. This keeps theme.json preset colors and custom inline colors authored in Gutenberg intact.

Core's **Outline** style is intentionally transparent with a two-pixel boundary and an ink-colored label unless the author explicitly selects a background or text color. The default Filled style retains its original ink/paper appearance. A long CJK/Arabic/Latin label may wrap inside a shrinkable button rather than extending past the 320px reading canvas. Native links keep their own accessible names, keyboard behavior and focus rings. Authors remain responsible for sufficient contrast when choosing custom colors; the theme must not silently overwrite those decisions.

`tests/browser/core-button-color-parity.spec.js` publishes a disposable real WordPress Page containing Core Buttons markup, deletes it after each run, and checks default/outline/preset/custom combinations at **320, 375, 390, 412, 768, 1440 and 1920px**, LTR/RTL, 200% text, forced-colors, keyboard focus, Axe and actual screenshots. It also uses authenticated Gutenberg Core block APIs to verify outline, preset and custom color serialization/parsing without modifying the editor post. `tests/test_core_button_color_parity.py` guards the CSS contract and editor stylesheet parity. No premium dependency, content ownership or plugin behavior is introduced.
