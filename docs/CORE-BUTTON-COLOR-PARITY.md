# Core Button palette and outline parity

Slateframe presents **native WordPress Core Buttons** without replacing Gutenberg's authored colors, changing saved markup, or adding JavaScript. The base Button rule owns bounded geometry and spacing. The theme's ink/paper fill and border apply **only to non-Outline Core Buttons**. WordPress Core's own palette classes and inline colors remain authoritative, while native Core CSS supplies wrapping, cursor and text alignment. This avoids duplicating Core styling and keeps the stylesheet within every existing runtime budget.

In forced-colors mode only, the theme restores system `ButtonFace` and `ButtonText` contrast and a `Highlight` focus ring even for authored inline colors. This avoids pale text on a browser-forced white button surface without changing the author's normal-mode palette. The browser fixture checks Axe contrast in forced-colors mode in both LTR and RTL.

Core's **Outline** style is delegated to WordPress itself: a transparent surface, a two-pixel boundary and inherited ink-colored label unless the author explicitly selects a background or text color. Both parent and legacy link-level Outline classes are excluded from Slateframe's filled fallback. The default Filled style retains its original ink/paper appearance. A long CJK/Arabic/Latin label may wrap inside a shrinkable button rather than extending past the 320px reading canvas. Native links keep their own accessible names, keyboard behavior and focus rings. Authors remain responsible for sufficient contrast when choosing custom colors; the theme must not silently overwrite those decisions.

`tests/browser/core-button-color-parity.spec.js` publishes a disposable real WordPress Page containing Core Buttons markup, deletes it after each run, and checks default/outline/preset/custom combinations at **320, 375, 390, 412, 768, 1440 and 1920px**, LTR/RTL, 200% text, forced-colors, keyboard focus, Axe and actual screenshots. It also uses authenticated Gutenberg Core block APIs to verify outline, preset and custom color serialization/parsing without modifying the editor post. `tests/test_core_button_color_parity.py` guards the CSS contract and editor stylesheet parity. The design explicitly depends on WordPress Core's Outline CSS; its real-WordPress browser assertions must pass before release. No premium dependency, content ownership or plugin behavior is introduced.
